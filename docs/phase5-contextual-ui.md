# 阶段 5：连接即空间的 UI 改版

> 2026-11-10 · 本轮只在 macOS App 实现，页面和选择规则留在共用 Flutter 层。

## 用户反馈与新的入口

此前启动后先出现“工作台”，所有 CLI/MCP 功能混在一个列表里。音乐连接的搜索、播放和播控分散在通用运行页与迷你播放器。用户希望连接音乐服务后直接进入播放器，其他连接也根据用途显示不同界面。

现在以**连接**作为主要导航对象：

1. 添加连接后打开这个连接的首页。
2. 重启后打开上次选中的连接；若没有历史选择，优先打开具备音乐搜索与播放动作的连接，否则打开列表中的第一个连接。
3. 音乐连接首页提供当前歌曲、播控、歌曲搜索和搜索结果中的播放/加入下一首。普通 CLI 首页显示命令与动作；MCP 首页按工具、资源、提示分组。
4. “所有功能”保留为次级入口，支持跨连接搜索；“管理连接”“活动”“设置”保留原有管理职责。

~~~text
侧栏                      当前连接首页
我的连接                  ┌─────────────────────────────────────┐
  音乐服务  ← 当前         │ 当前歌曲与播放状态       搜索歌曲    │
  Git                     │ 上一首 / 暂停 / 下一首   搜索结果    │
  项目 MCP                └─────────────────────────────────────┘

所有功能                  切换到 Git → 命令与动作
管理连接                  切换到 MCP → 工具 / 资源 / 提示
活动
设置
~~~

## 适配规则

`ConnectionExperience` 只读取公共 `Connection` 和 `Capability.presentation`：同一个 CLI 连接同时公布 `music.search` 与 `music.play` 时，进入音乐播放器。普通 CLI 落到命令与动作页；stdio/HTTP MCP 落到 MCP 功能页。连接名称即使叫“网易云音乐”也不会单独触发播放器。这样以后可以按明确的展示元数据增加其他专用界面，同时保留未知连接的通用入口。

音乐界面调用现有 `RuntimePort` 和 `MusicSession`，没有直接执行 CLI 或引入 macOS API。CLI 动作清单不能自行把搜索声明为可信的免确认操作，因此真实音乐连接首次搜索时会说明搜索词将交给该 CLI，并在用户允许后执行；本次 App 会话中同一连接的后续搜索不再询问。首次播放或播控仍单独确认，切换音乐连接后重新确认。状态仍由 Runtime 核对；若播放命令结果不确定，显示“正在确认”，不会把发送成功当成出声成功。

## 视觉取舍

播放器把当前歌曲和播控放在一个安静的主面板，搜索放在同一视图。由于 CLI 没有稳定提供封面图片，面板使用音乐符号占位，不伪造专辑封面。800×600 窗口用紧凑横排歌曲信息，保证搜索框留在首屏；较宽窗口将播放器与结果并排。App 顶部只保留全局搜索和添加连接图标，详细管理入口放在侧栏。

设计复核读取了 [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) 与 [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 的本地技能。采用与本任务相关的明确主角、渐进呈现、可见焦点、输入标签、错误与空结果提示及 Flutter `LayoutBuilder` 自适应。知识库自动推荐的 OLED 深色、荧绿按钮、英文展示字体和网页落地页结构与中文 macOS 工具及现有浅深色设计不符，未采用。Flutter 检索记录针对 3.44 版；当前工程为 3.47.8，最终以本机编译和截图为准。
