# 网易云音乐账号管理规划

> 2026-11-10 · SkillPilot 规划复核 · 当前版本只实施 macOS，公共契约保持跨端可复用。

**实施记录：** 已加入共用 `ConnectionAccountPort`、经 npm 包身份核验的 macOS 账号适配器、播放器账号面板、退出/切换确认，以及账号变化后的音乐状态清理。登录仍由 CLI 的 PTY 会话完成；面板从当前 CLI 输出中提取临时 `163cn.tv` 登录链接，在本地绘制白底二维码，不展示终端黑窗口。模拟 CLI、Widget 与原生 PTY fixture 已覆盖主要流程；真实账号已在本机退出，重新扫码登录仍需用户在手机上确认。

## 目标与边界

在 Aggregate 的网易云音乐连接首页显示当前账号，并提供扫码登录、退出登录和切换账号。这里管理的是 `@music163/ncm-cli` 使用的网易云音乐账号，不是 npm 仓库的 `npm login`。不要求用户把手机号、密码、Cookie、App ID 或 Private Key 输入 Aggregate。

`ncm-cli` 当前本机版本为 0.1.7。其帮助列出 `login`、`login --check`、`logout` 和 `user info`；[官方 npm 说明](https://www.npmjs.com/package/%40music163/ncm-cli)说明 `login` 在终端展示二维码，使用网易云音乐 App 扫码。本机 CLI 没有列出独立的“切换账号”或多账号保存命令。因此首版“切换账号”是退出当前登录后为新账号重新扫码，不提供账号列表或一键切回。切换途中取消或扫码失败时，界面明确显示未登录，不能假装恢复旧账号。

## SkillPilot 结果与采用范围

已用 SkillPilot 的 `skillpilot_plan` 按设计、测试、代码复核、安全和文档生成规划。它推荐的 21st.dev React 组件、Playwright 浏览器测试、Vercel 部署、Web 身份服务以及新 API Key 属于通用网站模板，与当前 Flutter macOS App 不匹配，本任务不安装。设计继续使用现有 `frontend-design` 与 `UI/UX Pro Max`；验证以 Flutter Widget 测试、Runtime fixture、macOS 原生窗口和现有 `tool/check.sh` 为主。若以后增加网页端，再评估 Playwright。

## 用户流程与界面

在播放器标题区域放一个低干扰的账号入口：登录时显示昵称和“已登录”，未登录时显示“登录网易云音乐”，检查中显示“正在检查账号”。点击后打开账号面板，不增加侧栏页面，也不把账号操作混进歌曲搜索结果。

| 状态 | 显示 | 可执行操作 |
| --- | --- | --- |
| 检查中 | 正在检查账号 | 等待或关闭面板 |
| 已登录 | 昵称、状态和连接来源 | 切换账号、退出登录、刷新状态 |
| 未登录 | 扫码登录提示 | 登录、刷新状态 |
| 正在扫码 | CLI 生成的二维码和明确的扫描说明 | 取消、二维码失效后重试 |
| 失败或未知 | 简短原因和下一步 | 重试、查看连接诊断 |

最初的 `TerminalView` 在实际窗口中裁切二维码，且黑色终端与播放器风格不符。本机 0.1.7 CLI 输出了完整的 `https://163cn.tv/...` 登录链接；面板现在只从已验证的 CLI 会话输出中提取该域名的链接，由 `qr_flutter` 本地绘制二维码。没有直接调用网易云登录接口，也不显示或持久化链接。若 CLI 更改链接格式，面板会停在“正在生成二维码”，用户可取消，并按故障排查文档在终端登录；这属于上游输出格式依赖。面板关闭时取消并回收登录进程。

退出登录前显示确认，说明本机 CLI 的当前登录将失效。切换账号前单独确认“先退出当前账号，再扫码登录新账号”；确认后依次退出、清理当前账号相关播放器状态、打开扫码面板。扫描成功后重新读取账号身份并刷新连接。操作期间禁用重复点击；取消、超时、网络失败、CLI 无响应各有明确反馈。账号变化后清除搜索结果、当前歌曲、播放授权和本会话搜索授权，避免旧账号内容留在新账号界面。

视觉沿用现有播放器的浅深色、排版和间距：账号入口是次要操作，播放器仍是页面主角。面板宽度适合二维码完整展示；800×600 窗口可滚动且主要操作可见。按钮有文字和语义标签，键盘可用 Tab、Enter、Escape 操作；焦点进入面板，关闭后回到账号入口。成功、失败和账号变化用可读状态反馈，不仅用颜色区分。

## 架构方案

```text
共用 Flutter 层
  MusicPlayerPage → AccountPanel → ConnectionAccountPort（类型化账号快照/操作）
                                     │
macOS 适配层                         └→ NeteaseCliAccountAdapter
                                          ├─ 已验证 @music163/ncm-cli 身份
                                          ├─ user info / login --check：读取状态
                                          ├─ login：现有 PTY + 临时链接读取/完成事件
                                          └─ logout：受控子进程、超时与结果校验
```

账号面板只依赖公共 Dart 账号合同和二维码绘制组件，不直接调用 `Process`、文件系统或 macOS API。运行端适配器仅对经过 `isNeteaseCliPackage` 核对、且连接可用的 CLI 开放这些按钮；普通 CLI、MCP 和仅名称相同的伪装程序不显示网易云账号入口。将来其他平台可实现同一账号合同，或对不支持的连接返回不可用。账号昵称只作为展示数据，登录凭证仍由 CLI 自己保存；Aggregate 不复制或持久化 Token、Cookie、临时登录链接与私钥。

状态读取应复用现有 `user info --output json` 验证逻辑，并核对 `login --check` 在本机版本中的返回结构和续期行为。仅提取展示所需的少量字段；原始响应、终端扫码输出和可能含凭证的错误不得写入活动记录或调试日志。登录完成与否必须以新的账号状态读取确认，不能仅因终端进程退出 0 就显示“已登录”。退出后再次读取状态，确认已登出才更新界面；结果不确定时显示“状态待确认”。

账号切换是带状态的流程：`已登录 → 确认 → 退出中 → 待扫码 → 验证新账号 → 已登录`。旧账号退出后不保存可恢复凭证。应先停止或隔离旧账号的播放会话；停止失败可继续切换，但必须提示播放器状态未确认。整个流程串行，连接切换、页面关闭、App 退出时取消等待中的登录终端；迟到事件不得覆盖新连接的账号状态。

## 分阶段实施和验收

### 阶段 0：核对 CLI 合同与最小实验

1. 在不登出真实账号的前提下核对当前 CLI 帮助、`user info`/`login --check` 的状态码和非敏感字段；用隔离配置或 fixture 验证未登录与错误状态。
2. 在隔离配置中确认 `login` 的二维码能否在现有 `TerminalView` 清晰显示、进程如何结束、取消是否彻底清理；确认 `logout` 的成功和失败输出结构。不得把真实凭证复制进测试目录。
3. 写下已验证的 JSON 字段、退出码、超时和二维码限制；若无法可靠判定登录完成，先补结构化终端完成事件，再进入 UI 阶段。

**通过条件：** 能区分已登录、未登录、网络/配置错误和状态不确定；二维码在目标窗口尺寸可扫描；不会因探测而退出当前真实账号。

### 阶段 1：公共合同与 macOS CLI 适配器

1. 定义 `AccountSnapshot`、账号操作状态和 `ConnectionAccountPort` 等公共 Dart 合同；在 macOS 端以已验证的 npm 包身份开启功能。
2. 实现账号读取、登录终端启动与取消、退出登录、超时/错误归一化。需要时为已有终端会话补跨端的完成事件，避免解析“进程退出”字样。
3. 为账号切换增加串行状态机与代际令牌；状态只在确认后更新，账号变更时使音乐会话和搜索结果失效。

**通过条件：** 普通 CLI/MCP 不出现账号操作；单次点击只启动一次命令；敏感原文不进入日志；取消和连接切换无遗留进程。

### 阶段 2：播放器账号界面

1. 添加标题区账号入口和账号面板，覆盖检查、已登录、未登录、扫码、切换、退出、失败状态。
2. 接入原生二维码、扫描提示与状态刷新；退出与切换使用不同的确认文案。
3. 用 `frontend-design` 校准视觉主次，用 `UI/UX Pro Max` 检查确认、反馈、键盘焦点和可访问名称；完成 800×600 与常用尺寸的浅深色布局检查。

**通过条件：** 用户不需要回终端就能完成登录/退出/切换；播放器搜索与播控仍可正常使用，账号状态在新旧账号间不会串联。

### 阶段 3：回归与本机验收

1. 使用伪 CLI fixture 覆盖登录成功、扫码取消/过期、退出失败、切换中断、网络错误、重复点击和连接切换；Widget 测试覆盖可见状态与焦点。
2. 运行 `sh tool/check.sh`，包括格式、分析、边界、公共包/App 测试及 macOS 构建；追加必要的浅深色截图与原生辅助功能树检查。
3. 在当前 Mac 上用实际 `ncm-cli` 验证 UI 流程。真实退出与切换会改变当前登录状态，执行前在界面中明确确认，并由用户完成扫码；只记录状态和结果，不记录二维码或凭证。
4. 更新用户指南、故障排查和本规划的实测结论；按仓库约定分段本地提交，推送仍需单独请求。

**通过条件：** 实际账号可在 App 内完成登录、退出、切换；新账号身份经 `user info` 验证；取消与失败路径不误报成功，旧账号的播放/搜索信息不残留。

## 尚待阶段 0 证实的点

- `login` 在本机 0.1.7 已观察到 `163cn.tv` 短链接，但尚未确认官方承诺该输出格式稳定；升级 CLI 后应复验链接提取。
- `login --check` 与 `user info` 的未登录、续期和网络故障返回形式；以本机 0.1.7 结果定解析规则。
- `logout` 是否停止现有播放守护进程；无论结果如何，App 必须清理和重新读取自身会话状态。

这些是实施前的验证项，不把未观察到的 CLI 行为写成既定能力。
