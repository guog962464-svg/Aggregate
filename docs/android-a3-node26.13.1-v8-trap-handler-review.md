# A3.6 Node 26.13.1 V8 trap-handler and Android signal-chain review

Reviewed 2026-11-27 against the current Android arm64-v8a candidate.

**Disposition: do not clear A3.6 for this candidate.** The default Node POSIX startup path can install Node's `SIGSEGV` WebAssembly wrapper even though V8's trap-handler support is compiled out. On stock AOSP Android 15, source traces the app-process `sigaction` lookup through ART's `libsigchain`; the Node registration replaces the chain's saved debuggerd action. If an ordinary native fault reaches Node's wrapper, V8 returns “not handled” and Node's no-predecessor path resets the disposition to `SIG_DFL` and raises. This is a source-level integration failure for that startup path. It is **not** a device reproduction or proof of the exact vendor process's fault/tombstone result.

The address-space condition is important: `CanEnableWebAssemblyTrapHandler()` does not check V8's compile-time support. It accepts an unavailable or unlimited `RLIMIT_AS`; otherwise it compares the limit with V8's reservation-size query. With support off, that query returns Node's 64-KiB minimum probe, so this check passes whenever the process limit is at least 64 KiB. The target process's actual limit was not read. Node also does not check the return from `V8::EnableWebAssemblyTrapHandler(false)` before setting its configured flag.

## Android 15 ART chain: source trace and boundary

This is more than evidence that ART installs a signal-chain handler. The pinned AOSP Android 15 release sources describe the relevant call and replacement semantics:

1. Android's dynamic linker calls `linker_debuggerd_init()` during process startup ([Bionic `linker_main.cpp:324`](https://android.googlesource.com/platform/bionic/+/refs/tags/android-15.0.0_r1/linker/linker_main.cpp#L324)); that calls `debuggerd_init()` ([`linker_debuggerd_android.cpp:64–75`](https://android.googlesource.com/platform/bionic/+/refs/tags/android-15.0.0_r1/linker/linker_debuggerd_android.cpp#L64)). `debuggerd_init()` registers the debuggerd `SA_SIGINFO` action for `SIGSEGV` ([system/core `debuggerd_handler.cpp:749–763`](https://android.googlesource.com/platform/system/core/+/refs/tags/android-15.0.0_r1/debuggerd/handler/debuggerd_handler.cpp#L749); registration list in [`handler.h:81–96`](https://android.googlesource.com/platform/system/core/+/refs/tags/android-15.0.0_r1/debuggerd/include/debuggerd/handler.h#L81)).
2. The Android 15 `app_process` build includes `libsigchain`; its build comment says this puts `libsigchain` symbols ahead of libc for app libraries ([frameworks/base `cmds/app_process/Android.bp:52–56`](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/cmds/app_process/Android.bp#L52)). `libsigchain` is marked global specifically so classloader-loaded app libraries resolve its symbols before libc ([ART `sigchainlib/Android.bp:34–40`](https://android.googlesource.com/platform/art/+/refs/tags/android-15.0.0_r1/sigchainlib/Android.bp#L34)).
3. ART `FaultManager::Init(true)` registers a special `SIGSEGV` handler through `AddSpecialSignalHandlerFn()` ([ART `runtime/fault_handler.cc:110–130`](https://android.googlesource.com/platform/art/+/refs/tags/android-15.0.0_r1/runtime/fault_handler.cc#L110)). `SignalChain::Claim()` calls `Register()`, which installs ART's kernel handler while saving the currently installed action in `action_` ([`sigchain.cc:277–303`](https://android.googlesource.com/platform/art/+/refs/tags/android-15.0.0_r1/sigchainlib/sigchain.cc#L277)). Under the startup order above, that saved action is debuggerd's handler.
4. Once the signal is claimed, ART's `sigaction` shim updates the saved `action_` when a later caller registers a handler; it returns the old action only if the caller supplies a non-null `old_action` ([`sigchain.cc:547–589`](https://android.googlesource.com/platform/art/+/refs/tags/android-15.0.0_r1/sigchainlib/sigchain.cc#L547)). Node supplies `nullptr`, so its wrapper replaces the saved debuggerd action without retaining it. This is the stock AOSP Android 15 source path; whether the target vendor image resolves the candidate's call through the shim has not been observed on-device.
5. ART first tries its special handlers, then calls `android_handle_signal`, then forwards to `action_` ([`sigchain.cc:430–545`](https://android.googlesource.com/platform/art/+/refs/tags/android-15.0.0_r1/sigchainlib/sigchain.cc#L430)). The debuggerd special callback returns true only for recoverable permissive-MTE or GWP-ASan cases; otherwise it returns false ([system/core `debuggerd_handler.cpp:805–833`](https://android.googlesource.com/platform/system/core/+/refs/tags/android-15.0.0_r1/debuggerd/handler/debuggerd_handler.cpp#L805)). Thus a regular native fault would normally reach the saved debuggerd action. If Node's wrapper runs, V8 returns false and Node has no previous Node callback on the default startup path; its fallback writes `SIG_DFL` through the same claimed signal and raises. ART's chain action can then be DFL, whose handler path removes ART's kernel handler and returns so the fault recurs under the default disposition (`sigchain.cc:530–540`). **This establishes a source-derived debuggerd bypass risk for the traced stock AOSP path; it does not establish that the target device actually takes this path or what report the OS produces.**

The static conclusion depends on ordinary Node initialization, the wrapper's address-space check passing, no embedder-installed Node `SIGSEGV` callback, stock AOSP Android 15 signal-symbol ordering, and the candidate's call resolving through ART's shim. Candidate object/source evidence supports the Node side; it cannot verify the vendor OS, actual runtime symbol binding, app-supplied flags/callbacks, or crash output. The Node wrapper only installs `SIGSEGV` on this non-Apple POSIX path; test `SIGBUS` separately as a chain control.

## Evidence still required to close A3.6

1. Add an Android-specific Node guard so V8-disabled builds do not install `TrapWebAssemblyOrContinue`; a startup argument alone is adequate only if every embedded/child entry path enforces it. Rebuild and bind new source/object/`libnode.so`/APK hashes.
2. On the supported-minimum Android API and Android 15 arm64 app processes, inspect the actual `sigaction` results before and after Node initialization for `SIGSEGV` and `SIGBUS`; verify the loaded `libsigchain`/`sigaction` resolution and Node flags/`RLIMIT_AS`.
3. In an isolated app process, test valid Wasm memory accesses and an out-of-bounds access that must produce a catchable Wasm `RuntimeError` using explicit bounds checks. In a disposable child, induce an ordinary native fault and verify process termination plus the expected debuggerd/tombstone evidence. Keep device reproduction separate from this static review; 16-KB device execution remains a distinct A3.6 gate.
4. Do not re-enable V8's signal trap handler without an independent V8 crash/security review and Android signal-chain review. V8's POSIX handler source explicitly requests crash-reporting/security review ([Node v26.13.1 `handler-inside-posix.cc:5–21`](https://github.com/nodejs/node/blob/v26.13.1/deps/v8/src/trap-handler/handler-inside-posix.cc#L5)). Node documents the inline-check behavior of [`--disable-wasm-trap-handler`](https://github.com/nodejs/node/blob/v26.13.1/doc/api/cli.md#L1092).
