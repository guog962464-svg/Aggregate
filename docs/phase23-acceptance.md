## 下一次验收的具体入口

1. 当前只验收这台 Mac。日后若启动其他机型、系统或独立用户的兼容矩阵，再按[发布检查](release-checklist.md)单独记录首次启动、真实旧版覆盖、CLI/stdio/HTTP MCP、Keychain 与退出清理。
2. 如需完整 VoiceOver 体验验收，由使用者在 0.3.7 解压版中逐条听检结果名称、来源及焦点顺序；本轮原生辅助功能树已能列出并激活搜索结果。
3. 已记录用户通过 Aggregate App 完成稳定播放、播控和实际出声的人工验收。若要求自动化回归，仍需解决早先探针与人工验收之间的差异；该差异不再阻挡当前 Mac 的用户验收结论。
4. 若将 HTTP MCP 浏览器 OAuth 纳入后续版本，先提供真实服务端、客户端注册与回调约束；实现授权码/PKCE、状态和发行方校验、令牌在系统凭证库的跨进程保存与撤销，再做服务端互操作验收。目前 UI 只接受静态 Bearer Token。
5. 正式分发另需 Developer ID 与公证凭证；用户当前无法取得，故不把签名/公证计入本次预览通过项。
