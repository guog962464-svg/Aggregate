# ADR 0001：macOS 阶段 0 技术选型

状态：阶段 1 候选，2026-11-09。

## 决定

1. macOS App 使用 Flutter 3.47.8 / Dart 3.13.7。首版先支持 Apple Silicon；生成工程的部署目标为 macOS 12.0，作为最低版本候选，尚未在 macOS 12 真机验证。
2. MCP 接入先用 `mcp_dart 2.4.3`，放在 `McpClientPort` 后。它已与独立 Python MCP SDK 2.3.0 的 stdio 和 Streamable HTTP 服务完成工具、资源、提示互操作。认证、分页、通知、取消和断线恢复仍需阶段 2 的针对性互操作验收。
3. macOS PTY 候选为 `flutter_pty2 3.0.0`。本机 Dart 探针已验证普通子进程、交互输入、尺寸变化、退出和进程组中断；App 内集成及打包运行仍需阶段 2 验证。Unix 上无法保证已脱离进程组的后代自动清理，Runtime 必须记录会话并在关闭时尽力清理。
4. 阶段 0 Flutter 壳采用内置 `MaterialApp` + `StatefulWidget` 和 `LayoutBuilder`。只有四个一级入口和一个未来任务页，当前无需引入状态管理或路由依赖。阶段 1 在实际跨页任务、后台运行与深链接需求明确后选路由/状态方案，保持 `RuntimePort` 不变。
5. 公共契约、Widget 与 UI 面向的端口只用 Dart/Flutter 公共 API。进程、PTY 与文件操作置于 macOS native Runtime 层。阶段 0 用静态边界脚本检查，后续纳入 CI。

## 依据与取舍

- `dart_mcp` 官方实验包的公开说明尚未覆盖 Streamable HTTP/授权；单独使用不足以满足本产品的远程 MCP 入口。社区包可工作，但新协议和安全边界必须继续验证。见 [dart_mcp](https://pub.dev/packages/dart_mcp)、[mcp_dart](https://pub.dev/packages/mcp_dart)。
- `flutter_pty2` 的会话 API 提供输入、输出、调整尺寸、信号和异步关闭；本机探针验证了当前 Mac 上的基本路径。包的跨平台宣称不作为其他端本版结论。见 [flutter_pty2](https://pub.dev/packages/flutter_pty2)。
- 全部动态能力通过 `RuntimePort` 出现，网易云音乐只作为连接器，核心不包含音乐专用流程。

## 后续门槛

阶段 1：明确路由/状态方案，完成契约序列化与 CLI 清单验证。阶段 2：真实 OAuth/鉴权服务、分页、通知、取消、超时、断线和多连接压力；在 `.app` 内实际运行 PTY；外部 CLI 效果不确定时不自动重试。上述验证前，不能宣称“任意 MCP/CLI 完全兼容”。
