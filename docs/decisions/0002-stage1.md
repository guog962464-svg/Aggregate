# ADR 0002：阶段 1 workspace 与 UI 状态边界

状态：已实施，2026-11-09。

## 决定

1. 使用 Dart pub workspace 管理 `app/`、四个公共包和阶段 0 探针；根目录只有一个 `pubspec.lock`。应用依赖公共包的本地 workspace 版本，不使用多份 path lockfile。依据 [Dart 官方 workspace 文档](https://dart.dev/tools/pub/workspaces)。
2. `aggregate_contracts` 定义模型、JSON 序列化、`RuntimePort` 与 `McpClientPort`；`aggregate_domain` 管理状态机、搜索/收藏/最近和 MCP 结果块；`aggregate_connectors` 负责 CLI 清单与参数展开；`aggregate_runtime` 在阶段 1 提供纯 Dart 的预览执行器。包依赖方向为 runtime → domain → contracts、connectors → contracts。
3. macOS App 的 `LocalRuntimePort.preview()` 只组装预览连接和能力并转发到纯 Dart `PreviewRuntime`。它不启动进程、不连接网络。阶段 2 的本机执行器替换预览后端时，UI 继续使用 `RuntimePort`。
4. Flutter 目前使用 `MaterialApp` 命名路由 `/`、`/run`，四个一级页面用 `IndexedStack` 保持搜索状态；功能运行页独立导航。状态由页面本地 `StatefulWidget` 与运行事件流维护。当前规模不引入第三方状态管理/路由库，阶段 2 出现后台多任务与深链接需求时再评估。
5. 页面只导入公共契约；平台依赖集中在 `app/lib/platform/macos` 和后续 native Runtime。CI 和本地脚本检查公共包及通用 Flutter 页面不导入 `dart:io`/`dart:ffi`/具体 MCP、PTY SDK。

## 边界

阶段 1 的结果和连接均明确标记“预览”。五页是可交互骨架，尚无真实连接添加、执行权限、动态复杂 schema、持久活动记录或终端渲染。GitHub Actions 工作流已编写，本机同等命令通过；没有远端 CI 运行记录。
