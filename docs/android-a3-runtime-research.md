# A3.6：Android Node 运行时与 16 KB 页状态

核对日期：2026-11-17。范围包括仓库固定的 fogtape `nodejs-mobile` Node 24.22.1-0 探针、官方 Node/nodejs-mobile 状态，以及基于 Node 24.22.3 的临时 Linux 重建。未启动模拟器；没有可用的 16 KB 实体设备。

## 结论

- **Node 24.22.3 临时候选的 mobile 版本号已修正并在 4 KB 真机验收：**在 fogtape 20 个移动补丁重放到官方 Node `v24.22.3` 的临时源码树中，将 `NODE_MOBILE_PATCH_VERSION` 从 `1` 改为 `3`，完整 GYP Release 目标重建后，隔离 NodeProbe Debug APK 的五轮生命周期结果均为 `process.versions.node=24.22.3`、`process.versions.mobile=24.22.3-0`；修正后的同一库在 curated 集 240 项以及 Android `parallel sequential` 配置子集 3,790 项均通过。后者拆为四片 948/948/947/947，无失败、挂起或崩溃。源码树 hash 仍不匹配 Node 24.22.1 recipe 的旧预期值，补丁语义与发行许可仍未完全审查，Node 其他测试类别也未覆盖。产物仅在 `/private/tmp`，不属于产品候选。详细摘要见本文末尾。
- **真机 16 KB 加载仍未知：**Aggregate 当前只有 LGE AN10 4 KB 页设备。静态 ELF/ZIP 检查不能代替 16 KB Android 内核下启动、JNI 加载、内存分配及 Node 行为验收。fogtape 项目的文档声称其发布流程会在 Pixel 9 16 KB 实体设备上执行启动和 N-API addon smoke；这属于其 release CI 的证据主张，不能表述成 Aggregate APK 已经完成 16 KB 实机验证。
- **运行时仍不可作为发布基线：**官方 `nodejs-mobile` Release 仍停在基于 Node 18.20.4 的版本；Node 18 已 EOL。fogtape 已发布的 Node 24 Android 包 `v24.22.1-0` 仍为 prerelease；本次 `v24.22.3` 是自行重建的实验产物，不是维护方发布或审阅过的 Android binary，也没有验证安全补丁对 mobile fork 的完整适用性。
- **A3.6 继续保持开放：**Node 24.22.3 临时候选的 mobile 版本元数据漂移已修正；五轮 NodeProbe 生命周期、curated 4 KB 真机集（240 项）及修正后 Android `parallel sequential` 配置子集（3,790 项）均通过。候选仍未经维护方发布；此前默认 all-suite 的 `message` 子集 11 项中 4 通过、7 失败，其他 Node 测试类别和 `--flaky-tests=skip` 排除项也未覆盖；真实 16 KB 实机运行未知。隔离 NodeProbe Release APK/AAB 静态检查通过但未签名；2026-11-17 发现原 AAB 实际含 Node 24.22.1，已重建为与 Node 24.22.3 test-signed APK 完全匹配的 AAB，并在 LGE AN10 4 KB 真机通过 Bundletool split 安装和 Node v24.22.3 smoke；AAB 本体未签名、split 使用非生产测试签名，不代表 Aggregate 产品 Release。Node `v24.22.3` 源 LICENSE 已确认为官方该 tag 的 44 项 LICENSE 加上移动 polywasm MIT 条目；fogtape recipe 顶层 LICENSE 是另一份 39 项清单，不是候选二进制的许可文件。主要 Android 构建依赖和 NDK notices 已完成静态分类，但不等于完整二进制 SBOM 或法律复核。NDK r27d cpufeatures 源码被静态编入 Node 库；NodeProbe 准备脚本现校验并打包 NDK 根 NOTICE，临时候选 APK/AAB 已重打包且静态容器检查通过（见下文）。产品端继续不开放 Node/npm/CLI。
- **移动端 suite/16 KB 口径更新（2026-11-17）：**fogtape 的完整移动设备 gate 只跑 `.status` 未跳过的 `parallel`/`sequential`；`message`、`es-module`、`pummel` 不属于该 gate。历史 4,588 项默认 all-suite 结果不能直接记为该 gate 失败；3,790 项子集通过因缺精确用例/runner 清单也不能记为完整 gate 通过。fogtape 当前 fork 的 BrowserStack 16 KB job 已从 `build.yml` 删除；公开 `24.22.1-0` run #78 展示的是 x86_64 Android API 30 emulator suite，不构成供应方或 Aggregate 16 KB 实机证据。详细依据见本文末尾的 2026-11-17 suite/workflow 对照。

## 16 KB 要求与剩余门槛

Android 官方指南规定：NDK r28 及以上默认用 16 KB ELF 对齐，但所有预编译共享库也必须各自符合；AGP 8.5.1 及以上负责兼容的 APK 打包。指南检查既包括 `LOAD` 段，也包括 APK 中 native library ZIP alignment 和存在共享 writable `LOAD` 时 GNU_RELRO 的边界。对于 16 KB 设备，代码不能假定 `PAGE_SIZE == 4096`，应使用 `getpagesize()` / `sysconf(_SC_PAGESIZE)`，并检查按页对齐的 `mmap()` 调用。Google Play 页面目前写明：面向 API 35 及以上的 64-bit 应用从 2027-02-01 起，更新必须支持 16 KB 页。

接下来不需要在没有实体 16 KB 设备时反复重做相同的静态检查。可先完成：

1. 升级或等待维护方发布基于最新 Node LTS 安全 patch 的 Android archive；将 upstream tag、mobile recipe commit、release SHA256SUMS、设备 CI run ID 一并固定。
2. 为候选 Release 逐个 ABI 对成品 APK/AAB 库做 ELF `LOAD`/RELRO、ZIP packaging 与依赖闭包检查；32-bit 只有解决其 `libc++_shared.so` 对齐后才能加入。
3. 完成包括 Node、OpenSSL、ICU、NDK C++ 运行库的许可/组件清单及安全更新责任。
4. 当 16 KB 实体设备可用时，执行一次实际安装与 Node/JNI/addon smoke，并保留 Android page-size 和运行时日志。若继续无设备，标为明确外部验收门槛，不标通过。

## 2026-11-14 补核：recipe 重建、补丁差异、许可清单与 curated 真机测试

- **recipe 固定基线可复现。**从 Node 官方 `v24.22.1` tag `ce7aaf1cee78b8cf0ce17364260535c418d3ed26` 重建并叠加 fogtape `recipe` 的 20 个补丁和 `mobile-src/` 后，树 hash 精确匹配 `expected-tree.txt`：`59a1f9b50b39080936dc0e78838b3945da83d8e0`。把上游切到 Node `v24.22.3` commit `e63cab040c09d43ceef8cb35508c40044614e906`，20 个补丁也全部干净应用；结果树为 `5b1a23adddf4b698abcfa45cc8d22de930c01b32`。后一个 hash 与固定值不同，是因为固定值对应 24.22.1 上游基线；没有更新 fork 的预期值，也没有把这次重建当成维护方审阅过的升级。

## 2026-11-15 `process.execPath` 自启动与目标 CLI 能力边界

- **最小失败复现：**在 LGE AN10 / Android 15 / API 35 / arm64 / 4 KB 页真机上，使用本机重建的 Node `v24.22.3-0` 候选与现有 Android Node test proxy，连续三次运行 `spawnSync(process.execPath, ['-e', 'process.exit(9)'])`。三次结果一致：`process.execPath` 为 `/system/bin/app_process64`，子进程状态为空、信号为 `SIGABRT`，stderr 为 `Error changing dalvik-cache ownership : Permission denied`，父 Node 进程可继续并报告结果。
- **正向控制：**同一运行时用 `spawnSync('/system/bin/echo', ['child-ok'])` 得到退出码 0、stdout `child-ok`、无 stderr。故证据只支持“嵌入入口自我重启/执行私有 JS 子进程失败”，不支持“所有 `child_process` 调用都失败”。实际边界受 Android 子进程启动方式和 Node mobile 构建共同影响。
- **源码定位：**候选 Node `src/env.cc` 通过 `uv_exepath()` 得到执行路径，`src/node_process_object.cc` 将其暴露为 `process.execPath`；Android 宿主则在 App 进程的 JNI 调用中通过 `node::Start` 启动嵌入 Node，Android Node 构建只交付共享库而不是可执行 `node` 文件。因此 `process.execPath` 指向宿主启动器 `/system/bin/app_process64`，不是可重用的 Node 命令。该观察来自本机重建候选及当前测试宿主，不能泛化为所有 Android Node embedder。
