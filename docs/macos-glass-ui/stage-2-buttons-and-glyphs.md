# UI-2：统一按钮与细腻点阵

> 状态：待执行 · 前置：[UI-1](stage-1-background-and-tokens.md)通过 · 后续：[UI-3](stage-3-coordinated-motion.md)

## 目标

在 Flutter 建立共用的玻璃按钮和颗粒工厂，所有按钮内部图案具有相同的颗粒质感与清晰度。

## 具体流程

1. 把 UI-0 操作清单映射到主操作、次级按钮、图标按钮、播控、导航、分段选择和危险操作。普通文字链接保持链接语义；原主题控件单独复用，不进入新按钮工厂。
2. 新按钮保留 Flutter 的可访问名称、焦点、键盘激活、禁用和命中语义；将装饰绘制与操作层分开。暴露图案、规格、启用/忙碌/选中状态和回调，避免把 Runtime 对象或权限逻辑塞进材质组件。
3. 新增统一点阵绘制层。所有图案和形变中间态通过同一颗粒工厂，不能让某两个图案走连续轮廓或不同锐化路径。
4. 使用 `CustomPainter`、Flutter runtime shader 与缓存纹理实现分层材质。先完成一组原生样本并比较成本，再固定方案；不照搬“每按钮一个 WebGL context”，不修改原主题的光学公式去迁就新按钮。UI-1 的背景场景接线单独审阅。
5. 缓存颗粒覆盖率、静态图案/纹理与可共享的 shader 程序；动画只更新姿态和必要参数。定义资源重建、尺寸/DPR/外观变化与释放策略。
6. 制作 12 类材质样本，并补齐实际页面中的返回、关闭、上一首/下一首、筛选、刷新队列等其余图案。同一种动作在不同页面沿用同一图案定义。
7. 在正常、焦点、悬停、按下、禁用、忙碌、选中和危险状态保存固定相位快照。检验放大样本与实际小按钮，不只看大图。

## 颗粒基准

以下数值来自 revision 5 的 32×32 图案设计坐标，不是每个按钮的实际 dp，也不替换原主题的 17×17 模型：

| 项目 | 设计值 |
| --- | --- |
| 逻辑网格 | 9×9 |
| 图案设计画布 / 原点 | 32×32 / 4 |
| 点中心节距 / 颗粒边长 | 2.7 / 1.9 |
| 颗粒圆角半径 | 0.64 |
| 边缘覆盖过渡 | 0.17 |
| 极弱局部光晕宽度 / alpha | 0.16 / 0.075 |
| 设计稿图案源纹理 | 128×128，设计坐标 4 倍采样 |
| 单颗粒覆盖率缓存 | 设计稿为 32×32 sprite，可在 Flutter 使用等效解析覆盖或缓存 |

这些数值是视觉起点。Flutter 纹理分辨率应结合目标显示大小与 DPR 核验：既不能用低分辨率近邻放大造成硬阶梯，也不能无条件为每个按钮创建大纹理。若实现方式不同，记录相同设计坐标下的等效值与对照证据。

“软润”表现为圆角颗粒、清楚内核、窄柔边和玻璃内部散射。不能靠整体大模糊、缩细图案、降低对比度或把相邻颗粒糊成实心块实现。

## 交付物与验收

- [ ] **UI-2.1** 12 类样本与全部实际按钮图案均来自同一颗粒工厂；运行与刷新没有单独的连续轮廓特例。
- [ ] **UI-2.2** 深浅色、1×/2×的实际小尺寸下，运行三角、刷新开口、复制双层、连接节点和护盾轮廓均可辨；颗粒核心与间隙清楚，无锯齿黑边或透明采样漏色。
- [ ] **UI-2.3** 同组按钮的玻璃厚度、倒角、接触阴影和光弧一致；功能差异通过图案与动作表达，不靠每项随意换色或更换材质。
- [ ] **UI-2.4** 按钮装饰不改变文字、焦点/命中范围；禁用按钮不触发回调，键盘与鼠标的业务调用次数一致。
- [ ] **UI-2.5** 新资源有明确缓存与释放路径，原主题逻辑符合 UI-0 冻结范围；“跟随系统”按钮可仅换呈现且保持原语义/映射；macOS 以外未启用新呈现。
- [ ] **UI-2.6** 原生材质板与设计稿在相同显示尺寸、外观和静态相位下完成对照，差异逐项记录，不能只写“看起来相似”。
